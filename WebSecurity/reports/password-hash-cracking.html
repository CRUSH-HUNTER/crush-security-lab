What is Password Hashing & Why?

مشکل بنیادی — ذخیره‌ی پسورد خام

اگه یه سایت پسوردت رو به‌صورت متن ساده (plaintext) ذخیره کنه و دیتابیسش لو بره، هر کسی همه‌ی پسوردها رو داره. هش‌کردن راه‌حل اینه:

پسورد اصلی admin123
→ MD5 →
ذخیره‌ی توی دیتابیس 0192023a7bbd73250516f069df18b500
ویژگی کلیدی هش: یک‌طرفه‌ست — از admin123 به هش می‌رسی، ولی از هش نمی‌تونی به admin123 برگردی. پس هیچ‌وقت پسورد اصلی توی دیتابیس نیست.

چطور لاگین کار می‌کنه اگه پسورد ذخیره نشده؟

کاربر پسورد وارد می‌کنه:   admin123
سرور هشش می‌کنه:           MD5("admin123") = 0192023a7bbd73250516f069df18b500
با دیتابیس مقایسه می‌کنه:  0192023a... == 0192023a... → ✓ ورود موفق

سرور هیچ‌وقت پسورد اصلی نگه نمی‌داره — فقط هش رو مقایسه می‌کنه.

چرا MD5 برای پسورد خطرناکه؟

مشکل ۱ — سرعت:
  MD5 برای سرعت طراحی شده (نه امنیت)
  یه GPU مدرن: ۱۰۰ میلیارد هش MD5 در ثانیه
  یه GPU مدرن: فقط ۱۰۰ هزار هش bcrypt در ثانیه
  فرق: ۱,۰۰۰,۰۰۰ برابر!

مشکل ۲ — بدون Salt:
  همه کسایی که پسورد "admin123" دارن → دقیقاً همون هش
  Rainbow Table: جدول از پیش محاسبه‌شده‌ی میلیون‌ها پسورد رایج
  کافیه هش رو توش جستجو کنی → فوری پسورد اصلی

مشکل ۳ — Deterministic:
  MD5("admin123") همیشه = 0192023a7bbd73250516f069df18b500
  هیچ‌وقت تغییر نمی‌کنه

چالش‌های مسیر — شکست hashcat

Obstacles — hashcat Failures & Root Causes
FAIL #1

فایل rockyou.txt پیدا نشد

دستور اجراشده:

hashcat -m 0 -a 0 hashes.txt rockyou.txt
# خطا: rockyou.txt: No such file or directory

دلیل: فایل rockyou.txt نصب شده بود ولی مسیر کامل داده نشده بود. hashcat فقط توی همون directory جاری دنبالش گشت.

راه‌حل: پیدا کردن مسیر واقعی با locate rockyou.txt و استفاده از مسیر کامل:

hashcat -m 0 -a 0 hashes.txt /usr/share/wordlists/rockyou.txt
FAIL #2

خطای حافظه — Not enough allocatable device memory

خطای دریافتی:

Not enough allocatable device memory or free host memory for mapping.

دلیل: بررسی با hashcat -I نشون داد:

Backend Device ID #01
  Type...: CPU
  Name...: Intel(R) Celeron(R) CPU N2840 @ 2.16GHz
  Processor(s).: 1
  Memory.Total.: 1480 MB (limited to 256 MB allocatable in one block)

سخت‌افزار یک ماشین مجازی VMware با CPU ضعیف (Celeron N2840) بود. بلاک حافظه‌ی قابل‌تخصیص فقط ۲۵۶ مگابایت — که حتی برای کرنل پایه‌ی hashcat کافی نبود.

تلاش‌های انجام‌شده برای رفع:

hashcat -m 0 -a 0 hashes.txt rockyou.txt -D 1        # فقط CPU
hashcat -m 0 -a 0 hashes.txt rockyou.txt -D 1 -w 1   # workload پایین
hashcat -m 0 -a 3 hashes.txt ?d?d?d?d?d?d -D 1 -w 1  # brute-force ساده

همه با همون خطا شکست خوردن — یه محدودیت سخت‌افزاری واقعی بود، نه مشکل تنظیمات.

SOLVED

راه‌حل جایگزین — اسکریپت Python بدون نیاز به GPU/OpenCL

به‌جای hashcat که به OpenCL و حافظه‌ی device نیاز داشت، همون منطق dictionary attack رو با Python خالص پیاده کردیم:

import hashlib

# هش‌های هدف رو لود کن
with open('hashes.txt') as f:
    hashes = set(line.strip() for line in f)

found = {}

# کل rockyou.txt رو خط‌به‌خط بخون
with open('/usr/share/wordlists/rockyou.txt', encoding='latin-1') as f:
    for word in f:
        word = word.strip()
        
        # هش MD5 هر کلمه رو حساب کن
        h = hashlib.md5(word.encode()).hexdigest()
        
        # با لیست هدف مقایسه کن
        if h in hashes:
            found[h] = word
            print(f"[+] {h} = {word}")
        
        # اگه همه پیدا شدن متوقف شو
        if len(found) == len(hashes):
            break

print("\nنتایج نهایی:")
for h, w in found.items():
    print(f"{h}:{w}")
چرا از set استفاده کردیم؟ جستجو در set پیچیدگی O(1) داره — یعنی هر بار که یه هش جدید می‌سازیم، چک کردن اینکه توی لیست هست یا نه فوریه، مستقل از اینکه چند هش داریم. اگه list بود، هر بار باید کل لیست رو scan می‌کرد — O(n).

اثر عملی — ورود مستقیم بدون SQLi

با این ۴ پسورد کرک‌شده، الان می‌تونیم بدون هیچ SQLi یا ابزاری مستقیم روی فرم لاگین عادی وارد بشیم:

Email:    admin@juice-sh.op
Password: admin123
→ ورود موفق به پنل ادمین (بدون هیچ payload یا bypass)
اهمیت در دنیای واقعی: حتی اگه SQLi رو ببندن، این credential ها هنوز کار می‌کنن. این دقیقاً چرایی مهمِ استفاده از bcrypt یا Argon2 با salt هست — با این الگوریتم‌ها کرک کردن همین ۴ پسورد ساده هم روی همین سخت‌افزار ماه‌ها طول می‌کشید.

درس‌های فنی از این مسیر

Technical Takeaways

وقتی ابزار اصلی شکست خورد — fallback هوشمندانه

این مسیر یه مهارت مهم رو یاد داد: وقتی ابزار تخصصی به‌خاطر محدودیت سخت‌افزاری کار نمی‌کنه، باید بتونی همون منطق رو با ابزارهای پایه پیاده کنی. ابزار فرق می‌کنه، اصل (dictionary attack) یکیه:

hashcat:  GPU → hash → compare    (سریع، به حافظه‌ی device نیاز داره)
Python:   CPU → hash → compare    (کند، ولی همیشه کار می‌کنه)
John the Ripper: یه گزینه‌ی سومه برای سخت‌افزار محدود

انواع حمله به هش‌ها — خلاصه

روشنحوه کارمناسب برای
Dictionary Attack هش کردن هر کلمه از یه wordlist و مقایسه پسوردهای رایج (admin123, password1)
Brute Force امتحان کردن تمام ترکیب‌های ممکن پسوردهای کوتاه (زیر ۸ کاراکتر)
Rule-Based اعمال قواعد روی wordlist (مثلاً admin→Admin1) پسوردهایی که تغییر کوچیک داده شدن
Rainbow Table جستجو در جدول از پیش محاسبه‌شده هش‌های بدون salt (مثل MD5 ساده)
ما از Dictionary Attack استفاده کردیم — با فایل rockyou.txt که ۱۴ میلیون پسورد لو رفته از دیتابیس‌های واقعی رو داره. ۴ پسورد از ۲۴ توش بود.
