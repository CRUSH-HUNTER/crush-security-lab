totpSecret — مفهوم، مکانیزم، و کاربرد امنیتی

از «کد ۶ رقمی چطور ساخته می‌شه؟» تا «اگه totpSecret لو بره چی می‌شه» — همه چیز به زبان ساده.

1

مشکل اصلی — پسورد به‌تنهایی کافی نیست

The Problem with Passwords Alone

چرا پسورد به‌تنهایی ضعیفه؟

پسورد یه چیز ثابته که همیشه یکیه. اگه:

- از یه سایت دیگه لو رفته باشه (credential stuffing)
- فیشینگ شده باشه (کاربر اشتباهی وارد کرده)
- توی دیتابیس هش‌شده باشه و کرک بشه (مثل همین کاری که ما کردیم)
- keylogger روی سیستم باشه

هر کسی که پسوردت رو داشته باشه، کامل به حسابت دسترسی داره.

راه‌حل: علاوه بر پسورد (چیزی که می‌دونی)، یه فاکتور دوم اضافه کن — چیزی که داری (مثل گوشیت). این می‌شه احراز هویت دومرحله‌ای (2FA).
2

TOTP چیه و چطور کار می‌کنه؟

Time-based One-Time Password — RFC 6238

تعریف ساده

TOTP یه الگوریتم استانداردشده (RFC 6238) هست که با ترکیب دو چیز، یه کد ۶ رقمی می‌سازه که هر ۳۰ ثانیه عوض می‌شه:

کد ۶ رقمی = HMAC-SHA1( totpSecret + زمان فعلی / 30 )

یعنی اگه هر دو طرف (سرور و اپ موبایل) یه کلید مشترک (totpSecret) داشته باشن، هر دو همزمان و مستقل از هم، دقیقاً همون کد رو می‌سازن — بدون نیاز به اینترنت.

مکانیزم گام‌به‌گام

STEP 01

ثبت‌نام اولیه (Setup)

وقتی 2FA رو فعال می‌کنی، سرور یه totpSecret رندوم می‌سازه (مثلاً JBSWY3DPEHPK3PXP) و یه QR code نشونت می‌ده. اپ Google Authenticator این QR رو اسکن می‌کنه و همین کلید رو داخل گوشیت ذخیره می‌کنه. سرور هم همین کلید رو توی دیتابیس ذخیره می‌کنه — همون فیلد totpSecret که توی جدول Users دیدیم.

STEP 02

تولید کد (Every 30s)

هر ۳۰ ثانیه، هم اپ گوشی و هم سرور، با همین فرمول یه کد می‌سازن: HMAC(totpSecret, floor(now/30)). چون هر دو همون کلید و همون زمان رو دارن، کدشون همیشه یکیه — بدون هیچ ارتباط شبکه‌ای.

STEP 03

لاگین

بعد از وارد کردن پسورد، سرور ازت می‌خواد کد ۶ رقمی هم وارد کنی. کدی که تایپ می‌کنی رو با کدی که خودش همین لحظه ساخته مقایسه می‌کنه. اگه یکی بود → ورود موفق. اگه نه → reject.

مثال واقعی با Python

این دقیقاً همون کاریه که Google Authenticator داخل گوشی انجام می‌ده:

import pyotp
import time

secret = "JBSWY3DPEHPK3PXP"   # همون totpSecret از دیتابیس

totp = pyotp.TOTP(secret)

print(totp.now())              # خروجی: مثلاً 123456
print(totp.now())              # بعد از 30 ثانیه: 891023 (عوض می‌شه)

# سرور هم همین کار رو می‌کنه و مقایسه می‌کنه:
print(totp.verify("123456"))   # True اگه درست باشه
نکته: این کد نیازی به اینترنت، سرور، یا ارتباط با گوشی کاربر نداره — فقط کلید (totpSecret) و زمان فعلی کافیه.

اگه totpSecret لو بره چی می‌شه؟

Security Implication of totpSecret Exposure

سناریو — از SQLi تا bypass کامل 2FA

همین chain of attack که روی Juice Shop انجام دادیم:

مرحله ۱: پیدا کردن SQLi روی فرم لاگین
         ' UNION SELECT 1,'',...-- 

مرحله ۲: استخراج totpSecret از دیتابیس
         SELECT email, totpSecret FROM Users WHERE totpSecret != '';

مرحله ۳: ساختن کد 2FA با همون secret
         import pyotp
         totp = pyotp.TOTP("secret_از_دیتابیس")
         print(totp.now())   # کد ۶ رقمی معتبر

مرحله ۴: لاگین کامل — حتی با وجود 2FA فعال
نتیجه: اگه totpSecret لو بره، 2FA کاملاً بی‌معنی می‌شه. دیگه فرقی نمی‌کنه که کاربر گوشیش دستشه یا نه — مهاجم می‌تونه همون کد رو خودش بسازه.

این یه یافته‌ی Critical در bug bounty هست

آسیب‌پذیری اصلی:    SQL Injection (روی فرم لاگین)
اثر ثانوی:          استخراج totpSecret از دیتابیس
نتیجه‌ی نهایی:       Bypass کامل 2FA + دسترسی به حساب کاربری

شدت (Severity):     Critical — 9.8 / 10 (CVSS)
چرا این‌قدر شدیده؟ چون 2FA معمولاً آخرین خط دفاعیه — یعنی حتی اگه پسورد لو رفته باشه، 2FA جلوی نفوذ رو می‌گیره. از بین بردن این لایه یعنی از بین بردن آخرین سد دفاعی.

ذخیره‌سازی درست در مقابل غلط

Secure vs Insecure Storage of totpSecret

❌ ناامن (مثل Juice Shop)

  • totpSecret به‌صورت plaintext در دیتابیس
  • قابل استخراج مستقیم با SQLi
  • هیچ رمزنگاری اضافه‌ای ندارد
  • یه SQLi = bypass کامل 2FA

✅ امن (روش درست)

  • totpSecret با AES-256 رمزنگاری شده
  • کلید رمزنگاری جدا از دیتابیس (HSM یا KMS)
  • حتی با SQLi فقط ciphertext می‌گیری
  • Rate limiting و lockout روی 2FA
نکته: حتی اگه دیتابیس کاملاً dump بشه، اگه totpSecret درست رمزنگاری شده باشه و کلید جای دیگه‌ای باشه، مهاجم نمی‌تونه ازش استفاده کنه.
5

تفاوت TOTP با روش‌های دیگه 2FA

TOTP vs Other 2FA Methods
روش نحوه کار آسیب‌پذیری
TOTP (Google Auth) HMAC(secret + time) اگه totpSecret لو بره، قابل bypass
SMS OTP کد به شماره موبایل SMS می‌شه SIM swap، SS7 attack، phishing
Hardware Key (YubiKey) کلید فیزیکی USB نیاز به دسترسی فیزیکی به کلید
Push Notification تأیید از اپ روی گوشی MFA fatigue attack (اسپم تأیید)
نتیجه: هیچ روش 2FA ای کامل نیست — ولی TOTP نسبت به SMS خیلی امن‌تره، به شرطی که totpSecret درست محافظت بشه.

آزمایش عملی — ساخت کد 2FA از totpSecret

Practical Lab — TOTP Code Generation from Database Secret

پیش‌نیاز

pip install pyotp

مرحله ۱ — گرفتن totpSecret واقعی از دیتابیس (با همون sqlitebrowser)

SELECT email, totpSecret 
FROM Users 
WHERE totpSecret != '' AND totpSecret IS NOT NULL;

مرحله ۲ — ساخت کد 2FA با Python

import pyotp

# مقدار totpSecret رو از دیتابیس اینجا بذار
secret = "SECRET_AZ_DATABASE"

totp = pyotp.TOTP(secret)

# کد فعلی (معتبر برای 30 ثانیه)
code = totp.now()
print(f"کد 2FA: {code}")

# چند ثانیه تا تغییر کد مونده؟
import time
remaining = 30 - (int(time.time()) % 30)
print(f"این کد {remaining} ثانیه دیگه معتبره")

مرحله ۳ — تست bypass

حالا با این کد ۶ رقمی برو به فرم لاگین Juice Shop، ایمیل و پسورد اون کاربر رو وارد کن، و وقتی 2FA خواست، همین کد رو بزن — باید بپذیره.

فقط روی Juice Shop محلی تست کن — استفاده از این روش روی هر سیستم واقعی بدون مجوز کتبی = جرم کیفری.
