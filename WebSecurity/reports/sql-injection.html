Database Enumeration

5.1 — Column Count Enumeration

برای تعیین تعداد ستون‌های query از ORDER BY به‌صورت افزایشی استفاده شد. 

' ORDER BY 1--
' ORDER BY 2--
...
' ORDER BY 13--
' ORDER BY 14--

درخواست‌های تا مقدار ۱۳ رفتار مورد انتظار داشتند، در حالی که مقدار ۱۴ باعث خطای دیتابیسی شد.

Observation: تعداد ستون‌های query مورد آزمایش حداقل تا 13 قابل استفاده بود و مقدار بعدی باعث خطا شد.

5.2 — UNION-Based Column Mapping

پس از مشخص‌شدن تعداد ستون‌ها، هر ستون به‌صورت جداگانه آزمایش شد تا اثر آن در ساختار رکورد و پاسخ application قابل تفکیک باشد. 

' UNION SELECT 1,NULL,NULL,NULL,NULL,NULL,NULL,NULL,NULL,NULL,NULL,NULL,NULL--

' UNION SELECT NULL,1,NULL,NULL,NULL,NULL,NULL,NULL,NULL,NULL,NULL,NULL,NULL--
Methodological Note: در آزمایش اولیه چند ستون هم‌زمان تغییر داده شدند که باعث ایجاد نتایج مبهم شد. روش تست به حالت single-variable تغییر داده شد تا اثر هر ستون به‌صورت مستقل قابل مشاهده باشد.

5.3 — Observed Column Mapping

با استفاده از مقادیر قابل تشخیص و تحلیل پاسخ application، نگاشت مشاهده‌شده‌ی ساختار Users به‌دست آمد:

5.4 — Data Extraction Validation

پس از مشخص‌شدن column mapping، از group_concat() برای بررسی امکان بازگرداندن چند مقدار از ستون email در یک پاسخ استفاده شد.

1,
'',

'','','','','','','',''--
Result: امکان بازگرداندن مجموعه‌ای از مقادیر جدول Users از طریق SQL Injection تأیید شد.

Root Cause

علت اصلی آسیب‌پذیری، استفاده ناامن از داده‌ی ورودی کاربر در query پایگاه‌داده و عدم استفاده‌ی مناسب از parameterized queries / prepared statements است.

در چنین شرایطی، داده‌ای که باید صرفاً به‌عنوان مقدار در نظر گرفته شود می‌تواند بخشی از منطق SQL تفسیر شود.

09

Remediation

Primary Recommendation

  • استفاده از prepared statements و parameterized queries برای تمام queryهای دیتابیس.
  • عدم اتصال مستقیم stringهای ورودی کاربر به SQL query.
  • اعتبارسنجی مناسب input در لایه application.
  • جلوگیری از افشای خطاهای خام دیتابیس به client.
  • اعمال least privilege برای database account.

Example — Safer Query Pattern

// Unsafe pattern
const query =
  "SELECT * FROM Users WHERE email = '" + email + "'";

// Safer pattern
const query =
  "SELECT * FROM Users WHERE email = ?";

db.get(query, [email]);
Expected Result: با استفاده از parameterized queries، payloadهای SQL به‌عنوان داده‌ی معمولی پردازش می‌شوند و قادر به تغییر ساختار query نخواهند بود.
